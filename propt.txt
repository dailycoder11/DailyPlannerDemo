I already have Phase 4 working with deterministic evals and one revision loop.

Now add **Phase 5: simple file-based memory**.

Create a `memory/` folder. Store each successful trip plan as one JSON file.

Only save plans whose final eval status is `PASS`.

Each memory file should contain at least:

- destination
- trip date
- budget per person
- number of people
- start time
- end time
- created time
- eval status
- final structured plan

Before running the normal planner, search existing memory files.

A previous plan can be reused if:

- destination/city matches,
- trip date is within ±30 days of the requested trip date,
- budget per person is within ±₹500.

If multiple plans match, choose the closest by date, then budget.

If a reusable memory is found:
- skip LLM/tool planning,
- load the stored final structured plan,
- show that plan to the user,
- log that memory was reused.

If no memory matches:
- run the existing Phase 4 flow normally,
- after a successful PASS result, save the final plan as a new JSON memory file.

Example logs:

```text
[MEMORY] searching previous plans
[MEMORY] match found: bengaluru_2026-11-15_1000.json
[MEMORY] reusing validated plan
```

or:

```text
[MEMORY] no suitable match
[PLANNER] running normal flow
[EVAL] PASS
[MEMORY] saved new trip plan
```

Keep this simple:
- no vector DB
- no embeddings
- no LLM-based memory search
- no summarization
- no multiple agents
